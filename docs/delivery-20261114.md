## 分支关系与使用方式

这些是**顺序依赖的交付分支**：第 N 批包含前 N-1 批，不能把所有分支都理解为互不依赖、可单独部署的实现。
前几批整理基础模块，完整 API 与界面在后续批次接入；部署与完整回归以第 10 批为准。

- 逐批审查：比较相邻分支，查看每批新增改动。
- 逐批合并：按 01 → 10 顺序处理，避免先合并上层分支后重复审查全部改动。
- 一次集成：最后的 `codex/10-integration-release-20261114` 已包含全部实现，可整体与 `master` 比较。
- 默认保留 `master`，推送功能分支不代表已合并、发布或部署。
- API Key、DPAPI 凭据、`.env`、本机数据库和运行日志不在交付文件中。第三方 ECharts 文件附许可证与来源说明。

## 保留的运行边界

- 后台队列默认容量 8、单执行线程；取消为协作取消，外部调用返回后检查，不能承诺立即停止远端模型。
- 多轮范围最多 8 轮；本标签页恢复最多保存 20 个服务器记录 ID，浏览器中不缓存原始凭据。
- 启用“执行前确认计划”时，规划结束必须确认才执行；关闭该选项可在规划完成后自动执行。
- 模型语义校验、结构化证据和建议验证不等于证明业务因果、源数据正确或经营收益。
- 源码、指标口径或权限发生变化后，旧断点会拒绝续跑，应重新查询，避免混用结果。
- 文档中的历史验收是阶段记录；当前完整实现应从第 10 分支运行，不能用某个早期分支代替集成版本。
