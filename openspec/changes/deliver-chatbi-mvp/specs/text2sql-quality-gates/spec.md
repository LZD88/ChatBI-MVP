# Spec Delta

## Purpose

该能力为 ChatBI MVP 建立可重复的质量门槛，用自动化测试和固定基准问题证明业务口径、安全约束、接口契约及 Text-to-SQL 执行结果没有发生回归。

## ADDED Requirements

### Requirement: 提供分层自动化测试
项目 SHALL 提供可在单一命令中运行的单元测试和集成测试，覆盖问题校验、指标识别、Prompt 规则、SQL 安全、API 响应和数据库结果映射。

#### Scenario: 运行完整测试集
- **WHEN** 开发者在测试环境执行文档化测试命令
- **THEN** 测试结果按单元与集成层次报告通过、失败和跳过数量，并以非零退出码表示失败

### Requirement: 维护固定 Text-to-SQL 基准集
项目 SHALL 维护版本控制的基准问题集，每个用例包含问题、难度、预期业务口径和可执行的预期 SQL，且 MUST 覆盖简单聚合、时间范围、多表关联、收入、成本、毛利和费用场景。

#### Scenario: 加载基准集
- **WHEN** 评估命令读取仓库内的基准文件
- **THEN** 每个用例均通过结构校验且具有唯一标识、问题、分类和预期 SQL

### Requirement: 以执行等价性评估 SQL
评估流程 SHALL 在隔离的演示数据库中执行生成 SQL和预期 SQL，并以结果等价性作为主要正确性指标，同时报告精确匹配率和执行失败率。

#### Scenario: 不同 SQL 返回等价结果
- **WHEN** 生成 SQL 与预期 SQL 文本不同但列语义和数据结果等价
- **THEN** 用例计入执行正确但不计入精确匹配

#### Scenario: 生成 SQL 无法执行
- **WHEN** 生成 SQL 触发安全拒绝、语法错误或数据库错误
- **THEN** 用例计入执行失败并记录稳定错误分类

### Requirement: 定义 MVP 验收门槛
发布候选版本 MUST 通过全部确定性单元与集成测试、全部 SQL 安全负例，并在固定模型与配置下达到文档化的基准执行正确率；默认最低门槛 SHALL 为 80%，且执行失败率 SHALL 不高于 10%。

#### Scenario: 候选版本达到门槛
- **WHEN** 测试全部通过且基准执行正确率不低于 80%、执行失败率不高于 10%
- **THEN** 质量报告将该版本标记为满足 MVP 验收门槛

#### Scenario: 候选版本未达到门槛
- **WHEN** 任一确定性测试失败、存在安全负例绕过、执行正确率低于 80%或执行失败率高于 10%
- **THEN** 质量报告将该版本标记为不满足验收门槛并列出失败用例

### Requirement: 测试不依赖生产机密
自动化测试 MUST 使用测试替身或显式提供的测试凭据，且默认测试命令不得要求生产 API Key、生产数据库或真实业务数据。

#### Scenario: 无外部凭据运行确定性测试
- **WHEN** 开发者未配置真实模型密钥而运行默认测试命令
- **THEN** 所有确定性测试使用测试替身完成，真实模型评估被明确分离或跳过
