# Spec Delta

## Purpose

该能力为非技术用户提供最小但完整的浏览器查询体验，使用户无需操作命令行即可提交业务问题、理解生成 SQL，并查看结构化数据结果或错误原因。

## ADDED Requirements

### Requirement: 提供自然语言提问界面
系统 SHALL 提供可在现代桌面浏览器中使用的单页界面，包含问题输入、示例问题和提交操作，并在输入无效时给出就地提示。

#### Scenario: 使用示例问题
- **WHEN** 用户选择一个预置示例问题
- **THEN** 界面将该问题填入输入区并允许用户编辑后提交

#### Scenario: 提交空问题
- **WHEN** 用户在输入为空或仅含空白时尝试提交
- **THEN** 界面显示输入提示且不发送查询请求

### Requirement: 展示查询处理状态
界面 SHALL 在查询进行期间显示明确的加载状态、禁用重复提交，并在请求结束后恢复可交互状态。

#### Scenario: 查询正在处理
- **WHEN** 查询请求尚未完成
- **THEN** 用户可见处理中状态且同一问题不能被重复提交

#### Scenario: 查询处理完成
- **WHEN** 查询成功或失败
- **THEN** 加载状态结束且用户可以修改问题后再次提交

### Requirement: 展示生成 SQL 与数据结果
查询成功时，界面 SHALL 展示生成 SQL、结果列和结果行，并 SHALL 对空结果与被截断结果给出明确说明。

#### Scenario: 返回多行结果
- **WHEN** API 返回列定义和一行或多行数据
- **THEN** 界面以可横向滚动的表格展示数据，并显示返回行数

#### Scenario: 返回空结果
- **WHEN** 查询执行成功但没有数据行
- **THEN** 界面显示“查询成功但没有匹配数据”且仍展示生成 SQL

#### Scenario: 结果达到上限
- **WHEN** API 标记结果已达到服务端行数上限
- **THEN** 界面提示当前仅展示前若干行，避免用户误认为结果完整

### Requirement: 提供可理解的错误反馈
界面 SHALL 根据稳定错误码区分输入、模型、Schema、SQL 安全、数据库和系统错误，并展示可行动的中文消息；原始堆栈与机密信息 MUST NOT 暴露给用户。

#### Scenario: SQL 被安全策略拒绝
- **WHEN** API 返回 SQL 安全拒绝错误
- **THEN** 界面说明查询未执行并建议用户缩小或重新表述问题

#### Scenario: 后端暂时不可用
- **WHEN** 请求超时、网络失败或服务返回不可用状态
- **THEN** 界面保留原问题并提供重试操作

### Requirement: 保留当前页面的查询历史
界面 SHALL 在当前浏览器页面会话中保留最近的有限条问题、SQL、结果摘要和状态；页面刷新后持久化历史不属于 MVP 要求。

#### Scenario: 连续提交多个问题
- **WHEN** 用户在同一页面会话中完成多次查询
- **THEN** 界面按时间顺序展示不超过配置上限的最近查询记录
