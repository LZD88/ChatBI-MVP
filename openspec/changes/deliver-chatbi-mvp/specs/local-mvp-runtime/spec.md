# Spec Delta

## Purpose

该能力保证 ChatBI MVP 能在一台新开发机上使用文档化配置和演示资产被重复安装、初始化、启动与诊断，而不依赖仓库外的隐含步骤或真实业务数据。

## ADDED Requirements

### Requirement: 提供可复现的依赖安装
项目 SHALL 声明运行和测试所需的完整依赖及受支持的 Python 版本，并 MUST 提供锁定依赖的安装方式。

#### Scenario: 在新环境安装项目
- **WHEN** 开发者在受支持的 Python 环境中执行文档化安装命令
- **THEN** 应用、索引初始化和测试所需依赖均可被安装且无需猜测额外包名

### Requirement: 提供安全的环境配置模板
项目 SHALL 提供不含真实密钥的环境变量模板，覆盖模型、Embedding、数据库、查询限制和日志配置；缺失必需配置时系统 MUST 快速失败并指出缺失项。

#### Scenario: 必需配置齐全
- **WHEN** 开发者根据模板填写有效的本地配置
- **THEN** 应用能够加载配置且不会输出密钥值

#### Scenario: 缺少模型 API Key
- **WHEN** 启动查询服务时未配置必需的模型凭据
- **THEN** 系统以明确配置错误停止启动或将查询能力标记为不可用

### Requirement: 提供演示数据库资产
项目 SHALL 提供与业务 Schema 一致的 MySQL 建表脚本、幂等种子数据和只读演示账号配置说明，数据 MUST 为虚构数据且能覆盖核心演示问题。

#### Scenario: 初始化空数据库
- **WHEN** 开发者对空的受支持 MySQL 实例运行初始化流程
- **THEN** 所需业务表、演示数据和只读查询权限被建立

#### Scenario: 重复初始化
- **WHEN** 开发者再次运行文档化初始化流程
- **THEN** 流程不会无控制地重复插入种子数据，并给出成功或可恢复提示

### Requirement: 提供 Schema 索引初始化
项目 SHALL 提供显式命令构建或重建表级和字段级索引，并 SHALL 在查询服务启动时检测索引状态。

#### Scenario: 首次构建索引
- **WHEN** 开发者在模型与 Embedding 配置有效时运行索引初始化命令
- **THEN** 表和字段索引被写入文档化的本地持久化位置

#### Scenario: 索引尚未构建
- **WHEN** 查询服务启动但本地索引不存在
- **THEN** 服务仍可按规格进入静态 Schema 回退模式且健康状态指出索引未就绪

### Requirement: 提供统一启动与健康检查
项目 SHALL 提供一个文档化启动命令，同时提供存活检查和就绪检查；就绪检查 MUST 分别报告应用、数据库、模型配置和 Schema 索引状态。

#### Scenario: 所有依赖就绪
- **WHEN** 应用、数据库、模型配置和索引均可用
- **THEN** 就绪检查返回成功并列出各依赖为可用

#### Scenario: 数据库不可用
- **WHEN** 应用进程存活但无法连接数据库
- **THEN** 存活检查仍可成功，而就绪检查报告数据库不可用

### Requirement: 提供完整运行文档
README SHALL 覆盖前置条件、安装、配置、数据库初始化、索引构建、启动、示例问题、测试和常见故障排查，并明确 MVP 的安全边界与非目标。

#### Scenario: 新开发者按文档启动
- **WHEN** 一名未参与开发的用户从全新检出开始按 README 操作
- **THEN** 用户能够启动 Web 界面并完成至少一个示例查询
