# 子任务三级失败管控验收

日期：2026-11-14。项目：`D:\学习资料\ChatBI`。

## 实现范围

| 层级 | 处理方式 |
| --- | --- |
| 局部自愈 | 受控错误分类、去除字面值的失败 SQL 结构、当前输出与输入契约共同反馈给执行模型；每次修复仍经过安全校验 |
| 权重分级 | 最终结果、显式核心任务及全部依赖强制为高权重；核心默认最多额外修复 3 次、辅助 1 次，模型不能突破配置上限 |
| 辅助降级 | 标记 skipped/soft_skip，相关辅助依赖跳过，主分析继续；报告列出缺失步骤及原因 |
| 核心熔断 | 当前请求后续调度停止，剩余步骤 blocked/circuit_blocked；不生成伪完整报告，进入 suspended |
| 人工续跑 | 重试、补充条件后继续、终止；同一查询 ID，复用已完成产物，默认最多人工续跑 3 轮 |

执行器当前串行执行，熔断阻止尚未调度的全部分支，没有并发分支可强制中断。权限拒绝和数据库断连不盲目改写 SQL。取消与终态保存使用同一把锁，修复了取消完成后又被标记为 cancelling 的竞态。

## 持久化和恢复

断点存入现有 SQLite 历史控制库的 analysis_checkpoints 表，而非 Redis。保存计划、已完成结果及产物、指标/Schema 上下文、恢复轮次、代码版本、口径版本与执行策略指纹。Decimal、date、datetime 使用显式类型序列化，不以浮点数替代精确数值，也不使用 pickle。

挂起期间释放执行线程。重启不自动付费调用模型；用户确认后恢复。续跑超时、异常或重启时保留最后已确认断点。口径、代码或权限配置变更拒绝恢复，防止混用结果。成功或主动终止后清理断点；批量清理保护挂起记录。单条断点上限 8 MB。

补充说明仅影响未完成步骤；不会自动切换到未经治理的“预估指标”。若需要改变已完成步骤的口径、粒度或时间范围，应重新查询。续跑沿用已完成结果，并在报告中提示新旧业务数据可能存在时间差；不承诺数据库跨重启快照一致性。
